# Ultimate CLAUDE.md Pack — готовый конфиг для вайбкодинга (2026)

Drop-in набор файлов для Claude Code, который собирает вместе пять рабочих
идей: поведенческие правила Карпатого, loop engineering Бориса Черного
(глава Claude Code в Anthropic), вертикальную структуру агентов с
независимыми проверяющими, байесовский слой принятия решений на
коэффициентах правдоподобия, потоковую память о проекте и роутинг задач
между моделями ради экономии токенов.

> Все конфиг-файлы внутри — на английском (модели надёжнее следуют
> англоязычным инструкциям). Этот README — на русском.

---

## Главный принцип

Это ПАКЕТ, а не один гигантский файл. Корневой `CLAUDE.md` держи маленьким
(< 200 строк — модели надёжно следуют ~150–200 инструкциям, и ~50 уже
съедает системный промпт самого Claude Code). Всё ситуативное лежит в
отдельных файлах и подгружается лениво.

Ментальная модель: **CLAUDE.md — это оперативка (RAM), а субагенты, правила
и docs — это диск.** Не грузишь весь диск в память на старте — подтягиваешь
по мере надобности.

## Как это работает (по компонентам)

### 1. Режим LOOP вместо чата
Ядро заставляет агента работать не «вопрос-ответ», а внутри цикла проверки:
каждая задача начинается с бинарной цели (да/нет проверяемо), сначала план с
проверкой на каждый шаг, потом исполнение. Это подход Черного: ты не пишешь
промпты по одному, ты строишь луп, который сам гоняет агента до цели.

### 2. Правила Карпатого (`rules/karpathy.md`)
Думай до кода, минимум кода, хирургические правки (каждая изменённая строка
трассируется до запроса), цель-driven исполнение. Снижает типовые ошибки
LLM: лишние абстракции, разросшиеся диффы, «улучшения» соседнего кода.

### 3. Вертикаль агентов (`agents/`)
Канон Черного: оркестратор -> задачи; каждая задача =
**implementer -> два НЕЗАВИСИМЫХ верификатора -> fixer**, луп до прохода
обоих. Ключевое правило: **один агент — одна специализация.** Если просить
одного агента «сделай и проверь», модель не выполняет проверку — она
предсказывает, как выглядел бы её результат. Поэтому проверяющие — отдельные
субагенты с чистым контекстом и read-only инструментами (без Write/Edit).

### 4. Байес на коэффициентах (`rules/bayes.md`)
Работаем в шансах (odds), а не в вероятностях — их можно просто перемножать:
`posterior_odds = prior_odds * LR1 * LR2 * ...`. Каждый LR (likelihood ratio)
— это множитель одного доказательства. Есть готовая таблица коэффициентов для
кода (тест воспроизвёл x8, «убрал код — симптом исчез» x15, зелёный тест
против гипотезы x0.3 и т.д.), пороги действия (>=0.90 действуй, <=0.30
выкидывай), протокол самокоррекции (первую правдоподобную причину нельзя
фиксировать без подтверждающего теста; всплыло опровержение — откатывай и
вычёркивай) и оценка цепи (5 «уверенных» шагов по 0.9 = 0.59 суммарно).

Честно: LLM — не вероятностная машина, и множители он присваивает сам.
Ценность не в «точных вероятностях», а в дисциплине: выписать конкурирующие
гипотезы, обосновать каждое обновление, гонять дешёвые опровергающие тесты
вместо самоуверенного «выглядит корректно». Обязательно калибруй таблицу под
свой репозиторий — дефолтные числа это только затравка.

### 5. Потоковая память (`docs/stream/`)
Три слоя, чтобы знание о проекте пережило сжатие/смерть контекста:
- **STATE.md** — «сейчас», перезаписывается (не растёт), только verified-факты.
- **CHANGES/** — append-only, строка на событие, новый файл на сессию.
- **LEARNINGS.md** — каждая пойманная ошибка становится постоянным правилом.
- **DECISIONS.md** — журнал решений с ссылкой на EV-таблицу байеса.
Агенты читают STATE на старте и пишут по ходу (не в конце!).

### 6. Роутинг моделей (экономия токенов)
Актуальная линейка (август 2026): Fable 5, Opus 4.8, Sonnet 4.6, Haiku 4.5.
Названий «Sonnet 5» / «Opus 5» пока нет — в файлах это РОЛИ-тиры, обновляй
model strings по мере выхода новых моделей.
- **Opus/Fable-тир** — архитектор и risk-assessor: декомпозиция, спеки,
  cross-cutting решения, финальный ревью. Кода не пишет.
- **Sonnet-тир** — implementer и fixer: один спек за раз, минимальный контекст.
- **Haiku-тир** — верификаторы, grep-разведка, суммаризация логов.
Главный расход — контекст, а не ответы. Раздутое ядро оплачивается в каждом
вызове каждого агента.

## Быстрый старт

1. Скопируй содержимое папки в корень своего проекта (или используй как
   шаблон нового репо).
2. Открой `CLAUDE.md`, заполни блок `Project` — ТОЧНЫЕ команды test/build/lint.
3. Прогони `/init`, смёрджи результат в блок `Project`, потом порежь вдвое.
4. Первую задачу сформулируй как бинарную цель -> отдай архитектору ->
   смотри, как крутится луп (implementer -> 2 верификатора -> fixer).
5. Каждую пойманную ошибку сразу пиши в `docs/stream/LEARNINGS.md`.
6. Через неделю: дистиллируй топ-правила из LEARNINGS в `forbidden.md` и в
   ядро `CLAUDE.md`.

## Мастхевы 2026, которые часто упускают

1. **Хуки > инструкций.** Любое «must always» — детерминированный хук
   (exit code 2 блокирует), не текст. Пример в `.claude/hooks/`.
2. **`memory:` у субагентов** (Claude Code >= 2.1.33) — персистентная память
   на агента: верификатор копит паттерны багов репо между сессиями.
3. **Auto memory** (>= 2.1.59): Claude сам пишет заметки, `/memory` — аудит.
4. **`/loop` и `/goal`** — нативные команды лупа; стрим-файлы это его память.
5. **Plan mode** перед правкой незнакомого кода.
6. **Git worktrees** — обязательны при параллельных агентах.
7. **Permissions / sandbox** — deny-list на .env, прод-креды, force-push.
8. **Стоп на флип-флоп** — если проверка чередует PASS/FAIL, это флейки-тест
   или неверный спек; луп обязан остановиться, а не жечь токены.
